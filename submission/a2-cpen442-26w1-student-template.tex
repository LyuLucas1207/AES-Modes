\question{15} Which of \texttt{lyrics-ciphertext1.txt}, \texttt{lyrics-ciphertext2.txt}, and \texttt{lyrics-ciphertext3.txt} is AES-ECB, and how did you tell?

\begin{answer}
    \textbf{AES-ECB is:} \texttt{lyrics-ciphertext3.txt}

    \textbf{Explanation:}
    Each file stores Base64 text, not the raw ciphertext. I decoded it with
    \lstinline{base64.b64decode(path.read_text().strip())}, then split the
    resulting bytes into 16-byte AES blocks.

    \texttt{lyrics-ciphertext1.txt} has 181 blocks, all distinct.
    \texttt{lyrics-ciphertext2.txt} has 182 blocks, all distinct.
    \texttt{lyrics-ciphertext3.txt} has 182 blocks but only 171 distinct ones.
    Six block values repeat, including
    \lstinline{95135c6db929844c03dec22524eddc6c} four times and
    \lstinline{6b8273a4705485a6f43133c9061c643e} four times.

    In ECB each block is encrypted on its own, so \(M_i = M_j\) implies
    \(C_i = C_j\). The lyrics repeat 16-byte phrases, and those repeats show
    up as identical ciphertext blocks only in \texttt{lyrics-ciphertext3.txt}.
    CBC and CTR do not preserve \(M_i = M_j \Rightarrow C_i = C_j\), so that
    file is AES-ECB.
\end{answer}

\question{15} Which one is AES-CTR, and how did you tell?

\begin{answer}
    \textbf{AES-CTR is:} \texttt{lyrics-ciphertext1.txt}

    \textbf{Explanation:}
    The plaintext, \texttt{lyrics-plaintext.txt}, is 2896 bytes. That length
    is already a multiple of 16, but ECB and CBC still apply PKCS\#7 padding:
    an aligned plaintext gets one extra block of sixteen \lstinline{0x10}
    bytes before encryption. CTR does not pad, so its ciphertext stays the
    same length as the plaintext.

    After the same Base64 decode, the lengths are:

    \begin{center}
    \begin{tabular}{lr}
        \texttt{lyrics-ciphertext1.txt} & 2896 bytes \\
        \texttt{lyrics-ciphertext2.txt} & 2912 bytes \\
        \texttt{lyrics-ciphertext3.txt} & 2912 bytes \\
    \end{tabular}
    \end{center}

    Ciphertexts 2 and 3 are one block longer than the plaintext.
    Ciphertext 3 is the ECB file from Question 1, so the other long file is
    CBC. The short file matches the plaintext length and has no extra padding
    block, so \texttt{lyrics-ciphertext1.txt} is AES-CTR.
\end{answer}
